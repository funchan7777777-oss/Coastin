# Coastin Project Notes

- Keep the app Flutter/Dart first and iOS-focused.
- Do not run builds or tests after routine implementation tasks unless the user explicitly asks.
- Prefer Coastin-specific names with business meaning over generic names like item, data, model, page, or card.
- Domain fields should describe the shoreline planning context, such as tide timing, route comfort, cove pauses, harbor readiness, and local approach notes.
- Keep generic starter copy out of app screens. User-facing text should stay calm, lawful, coastal, and useful.
- Add files under meaningful feature folders in `lib` instead of flattening everything into one or two directories.
